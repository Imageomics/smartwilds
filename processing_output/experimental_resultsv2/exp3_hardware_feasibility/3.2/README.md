# Exp 3.2 Prediction Model

This directory implements README section 3.2 for Exp 3: the predicted hardware
feasibility grid over case study, hardware tier, and policy.

## What This Runs

The experiment combines three inputs:

1. Case-study event traces from `../../exp6_3_case_studies/traces/`.
2. The source-backed benchmark table generated by `../3.1/benchmark_table.py`.
3. Yuanyang's policy logic, copied into this directory as `policies.py` and
   `control_theoretic_policy.py`.

For each `(case_study, tier, policy)` cell, `prediction_model.py`:

1. Loads the case-study trace.
2. Replays the selected policy event by event.
3. Counts policy actions: `process`, `drop`, and `defer`.
4. Keeps only `process` events for immediate compute-load prediction.
5. Converts processed events into p95 hourly arrival rates per modality.
6. Maps each modality to a model:
   - `camera_trap -> megadetector`
   - `bioacoustic -> birdnet`
   - `drone -> sam3`
   - `citizen_science -> bioclip`
7. Looks up model latency for the selected hardware tier in
   `../3.1/benchmark_table.csv`.
8. Computes utilization and p95 response latency with an M/M/1 queueing model.
9. Emits a feasibility verdict:
   - `feasible`: utilization < 70% and p95 latency is within SLO.
   - `degraded`: utilization < 100% and p95 latency is within 1.25x SLO, but
     the cell is not cleanly feasible.
   - `infeasible`: utilization >= 100%, p95 latency exceeds the degraded band,
     or a required model-tier latency is unsupported.

Rows with `NaN` latency in the benchmark table are treated as unsupported. If a
trace needs an unsupported model on a tier, the cell is marked `infeasible` and
the `bottleneck` column starts with `unsupported:`.

## Files

| File | Purpose |
|---|---|
| `prediction_model.py` | Main prediction model and CSV generator. |
| `plot_predicted_grid.py` | Builds the single heatmap PDF from the grid CSV. |
| `run_predictions.sh` | Runs 3.1 benchmark generation, 3.2 prediction, and plotting. |
| `policies.py` | Yuanyang policy interface and process/event/adaptive policy logic. |
| `control_theoretic_policy.py` | Yuanyang control-theoretic policy implementation. |
| `results/predicted_feasibility_grid.csv` | Generated table for Table V / downstream analysis. |
| `results/predicted_feasibility_heatmap.pdf` | Generated heatmap, with `case_study / policy` rows and tier columns. |

## How To Run

From this directory:

```bash
./run_predictions.sh
```

From the repository root:

```bash
processing_output/experimental_resultsv2/exp3_hardware_feasibility/3.2/run_predictions.sh
```

The script regenerates:

```text
../3.1/benchmark_table.csv
results/predicted_feasibility_grid.csv
results/predicted_feasibility_heatmap.pdf
```

You can also run the pieces separately:

```bash
python ../3.1/benchmark_table.py
python prediction_model.py
python plot_predicted_grid.py
```

## Output Columns

`results/predicted_feasibility_grid.csv` contains:

| Column | Meaning |
|---|---|
| `case_study` | Case-study ID, e.g. `CS1`. |
| `workload` | Case-study workload name from the trace manifest. |
| `tier` | Hardware tier from the benchmark table. |
| `policy` | Policy passed to `get_policy()`. |
| `utilization_pct_predicted` | Aggregate predicted utilization across processed modalities. |
| `p95_latency_ms_predicted` | Worst per-modality predicted p95 queue response latency. |
| `slo_target_ms` | SLO from the case-study manifest. |
| `slo_met_predicted` | Whether predicted p95 latency is within SLO. |
| `bottleneck` | Highest-utilization modality/model, or unsupported model-tier pair. |
| `verdict` | `feasible`, `degraded`, or `infeasible`. |
| `measured` | Always `False` for Exp 3. Exp 3.5 is the measured laptop anchor. |
| `calibration_gap_pct` | Empty for Exp 3; filled by Exp 3.5. |
| `modeling_notes` | Policy action counts and per-modality rate/utilization details. |
