    SmartWilds — supplemental material¶

    Camera-trap update (2026-11-08). The legacy camera counts, Event hierarchy, first-generation Tree-of-Life method statements, and camera detection-arrival rows in this historical supplement do not describe the current camera release. The canonical camera release has 72,775 original-SAM3-geometry Occurrences, 19,785 camera Events, a 235,778-image inventory, and 70,466 Campaign-2 operational-inference arrivals. Its combined multimodal table has 401,602 Occurrences and 22,242 Events. See CAMERA_TRAP_RELEASE.md for the release-facing scope and provenance. The historical sections remain for auditability and must not be used as current camera-release statistics.

    Supplemental material for the SmartWilds datasets. This contains the full data inventories details, the timestamp-repair methods, the standards crosswalk, the field dictionary, the arrival statistics, and the complete defect inventory.

    Last updated: 2026-11-10. Release: SmartWilds release build 2026-10-22, camera tables updated 2026-11-08. It supersedes the 2026-07-24 integration pass. Paths such as processing_output/... are relative to the project archive; the released files are in the per-modality datasets of the SmartWilds collection.

    S1. Extended glossary¶

    Term Source Meaning in this release What it is not
    Event Darwin Core A sampling act with a date, location, protocol, and parentEventID. Five levels in use: Project, SensorDeployment, AudioRecording, MediaEvent, ObservationSession. Not an arrival in a stream. One Event can contain 10⁵ arrivals.
    Occurrence Darwin Core One organism record at a place and time, linked by eventID. Usually one detection crop. Not an individual animal. Adjacent drone frames yield many Occurrences of the same animal.
    eventType Darwin Core The level of the hierarchy a row occupies. Not the modality; modality is carried by parentEventID and modality_type.
    basisOfRecord Darwin Core MachineObservation for every detector-derived row; HumanObservation for citizen-science and text records and for the 12 human-added drone starling boxes. Not a quality statement. See identificationVerificationStatus.
    identificationVerificationStatus Darwin Core Vocabulary differs by table. Post-triage camera traps: human-reviewed, machine-resolved. Drones and bioacoustics: unverified, validated, plus human-supported; limited-resolution for the drone starling supplement. Citizen science and text: verified by expert. Counts in S9.3. Not a confidence score. machine-resolved and unverified are both machine labels; a validated or human-reviewed record was reviewed by a person.
    dataGeneralizations Darwin Core States whether a coordinate is an observed position, a sensor position, a projected estimate, or a platform-telemetry fallback. Not a precision estimate; see coordinateUncertaintyInMeters.
    informationWithheld Darwin Core Records where locality precision was reduced for sensitive taxa. —
    Sampling effort Humboldt ext. Acquisition quantity actually expended, per modality: camera observation-days, recorder-hours, flight-minutes, visitor sessions. Not comparable across modalities. Not a detection count.
    Arrival systems One item entering a processing stream. Two layers measured: acquisition (image capture, WAV file) and detection (an Occurrence). Not a Darwin Core Event.
    Deployment systems One physical installation of one device at one site over one interval. Not a device. One device yields several deployments across campaigns.
    Duty cycle systems Fraction of wall-clock time a device was scheduled to acquire. Not uptime. A device can be on-schedule and dead.
    Detection systems A model output: a SAM3 box, a BirdNET hit. Not an identification.
    Identification Darwin Core A taxonomic assignment with a stated verification status. Not implied by a detection.
    locationID Darwin Core Stable identifier for a fixed sensor position or a drone session origin. Null for locality-only records. Not a comparable spatial sampling unit across modalities.
    Coverage systems Distinct (date, hour) pairs containing ≥1 Occurrence, per modality. Not area surveyed. Not detection probability.
    Campaign this release One field deployment interval. Three: C1 Jun 30–Jul 3, C2 Aug 4–28, C3 Sep 8. Not a Darwin Core term.

    S2.3 Configuration as workload multiplier¶

    Parameter Range in deployment Workload effect
    Burst length 3 or 5 frames/trigger Direct 3× or 5× multiplier on raw images per ecological event
    Capture mode photo-only / photo+video / hybrid Video adds a 10–15 s clip per trigger: large storage, frame-extraction compute
    Resolution 4 MP / 8 MP / 4K Bytes and per-image inference time
    PIR sensitivity High, Level 9, motion-detect Higher sensitivity → more triggers and more blanks
    Inter-trigger delay 0 / 10 / 20 s Longer delay suppresses repeat triggers, lowering effective arrival rate
    HFOV 55°–120° Wide-angle covers more area at lower pixel density per animal
    Cellular uplink Reveal Pro 3.0 only The only device in the deployment that could participate in near-real-time coordination
    Timelapse TW01-CT02 C1 only Adds a scheduled arrival stream independent of PIR

    S6. Drone ground projection¶

    The campaigns were flown for population estimation and behavior, not geolocation. Platform GPS localizes a detection to a known pasture, which is the operative spatial reference. Per-animal projection is an optional refinement provided for completeness; no result in any of the three papers depends on it. Monocular distance estimation from a moving platform to moving subjects is unreliable and is not established practice in aerial wildlife survey.

    Status Detections Share
    ok (projected position available) 247,340 77.9%
    invalid_altitude 27,306 8.6%
    missing_drone_gps 24,467 7.7%
    horizon_ray (camera near level) 18,324 5.8%
    out_of_range 122 0.04%

    Method: convert the bbox bottom-center pixel to a camera ray, rotate by heading/pitch, intersect with a flat ground plane, project the offset from platform GPS. Dominant error sources: gimbal-pitch convention, terrain relief, altitude source, video stabilisation, FOV assumption, and whether bbox bottom-center is the animal's ground-contact point.

    Camera-trap coordinates use the pinhole method from https://github.com/Imageomics/camera-trap-geolocation: bbox height → range, bbox horizontal offset → bearing, projected from the camera GPS. Assumes flat ground and a uniform 0.9 m target height — the dominant error term at a site holding animals from geese to Père David's deer.

    Known analysis hazard. An internal audit found a spatial figure that plotted projected animal positions and platform-telemetry positions together without distinguishing them: 15.66% of 292,106 plotted drone points were platform coordinates. The status field was present and correct; the script did not read it. The release ships a validator that fails when an analysis consumes drone coordinates without constraining the status column.

    S9. Models, parameters, and measured accuracy¶

    Manual annotation does not scale to sensor-network volume: human-reviewed labels are under 1% of the release and consumed the review capacity available. Semi-automated analysis is therefore the realistic condition, and we use current state-of-the-art models so that reported quality reflects what a practitioner adopting today's best tooling would obtain.

    Labels were produced in two generations, and the released tables carry both. The first generation labeled every SAM3 box with a BioCLIP Tree-of-Life taxon; it still describes the operational drone table and the merged cross-modal snapshot. The second generation (October–November 2026) replaced the camera-trap labels with embedding-based triage plus targeted human review (S9.1), and added a seven-video human-annotated drone reference set with a manual starling supplement (S9.2).

    Stage Model Role
    Visual segmentation SAM 3 bounding boxes on camera-trap images and drone frames
    Visual classification, first generation BioCLIP Tree-of-Life (TreeOfLife-200M) top-1 taxon with full rank hierarchy, top-5 retained; operational drone labels
    Label triage, second generation Resolve–Clear–Defer prototype triage over proposal embeddings routes proposals to human review and resolves the rest by similarity to reviewed examples; operational camera-trap labels
    Acoustic detection BirdNET detections with frequency bounds and offset into the WAV
    Water/lake masking SAM 3 lake/water masks for habitat-association analysis

    S9.1 Camera-trap labels (post-triage)¶

    Operational camera-trap Occurrences are SAM3 animal proposals labeled by Resolve–Clear–Defer triage. The triage selects proposals for human review and resolves the remainder by similarity to reviewed examples; labelProvenance records the outcome on every row, with the triage round where recovered.

    labelProvenance identificationVerificationStatus Occurrences
    triage_reviewed human-reviewed 1,760
    triage_resolved machine-resolved 70,808
    triage_forced_1nn machine-resolved 201
    Total 72,769

    Forced nearest-neighbour labels did not meet the triage confidence rules and may be wrong; exclude them unless label noise is tolerable. Box geometry is never edited (geometryProvenance = SAM3), even when the label was human reviewed. The table keeps only reviewed or resolved animal proposals: cleared and background proposals, boxes with a shorter side below 32 px, boxes overlapping the per-resolution ROI mask, and frames on the privacy exclusion manifest are excluded, so an image without an Occurrence is not evidence that no animal was present. Twelve taxa occur: milu (Père David's) deer, Przewalski's horse, Canada goose, Sichuan takin, trumpeter swan, killdeer, European starling, barn swallow, and the broad labels bird, butterfly, dragonfly, and insect.

    A separate human-reviewed reference set of 2,067 boxes on 198 selected ungulate and waterfowl images (881 Canada goose, 627 milu deer, 349 Przewalski's horse, 149 Sichuan takin, 61 trumpeter swan) is released beside, not inside, the Occurrence table. Taxonomy and geometry were both reviewed; 1,552 boxes share a SAM3 proposal's geometry and 515 are human edits or additions, and the set is not filtered by the 32 px or ROI rules. The images were selected for review, so the set is not a random or exhaustive test split. Triage label accuracy against this reference set has not yet been reported.

    S9.2 Drone labels: operational table and seven-video reference set¶

    Operational table. The 318,203 machine drone Occurrences remain first-generation labels: a SAM3 box on every 15th frame with a top-1 BioCLIP Tree-of-Life taxon. The only measured accuracy for that labeler comes from human-annotated camera-trap subsets:

    Analysis Level n Precision Recall F1 / accuracy
    SAM3 animal localization, camera traps IoU ≥ 0.50 1,125 0.866 0.845 0.856
    Tree-of-Life taxonomic assignment class 951 0.845
    order 951 0.660
    family 951 0.463
    genus 951 0.322
    species 951 0.271

    Usable statement: class-rank labels support screening and triage; species-rank labels require curation; anything aggregating across ranks is uninterpretable. A single headline accuracy anywhere in the 0.27–0.85 range would mislead. Corroborating evidence: the taxonomy crosswalk holds 12,577 label keys, of which only 4 consist entirely of expert-verified records and 16 contain accepted names with mixed verification evidence.

    Seven-video reference set. Seven drone videos were human-annotated on 1,089 sampled frames for four focal classes, with onager observations excluded: 20250703_parrotanafi_1, _2, _5 (C1), 20250811_DJI_01, 20250818_parrot_01, _02, and 20250825_parrot_01 (C2). The corrected reference holds 27,159 four-class boxes (the localization audit below was run against 27,180 before the final manual review): Père David's deer 21,177, Sichuan takin 3,293, Przewalski's horse 2,066, Canada goose 644. It is delivered as COCO JSON with provenance, a frame-to-proposal mapping, and the audit files.

    SAM3 localization against the reference (35,312 proposals, one-to-one matching):

    IoU Precision Recall F1
    0.25 0.758 0.985 0.856
    0.50 0.749 0.973 0.847
    0.75 0.740 0.961 0.836

    Per-class recall at IoU 0.25: Przewalski's horse 0.961, Père David's deer 0.985, Sichuan takin 0.993, Canada goose 1.000. Per-video recall at IoU 0.25 ranges from 0.958 (20250818_parrot_02) to 0.999 (20250825_parrot_01).

    Resolve–Clear–Defer prototype triage was then run over the full proposal pool (seed 3, density-moderated k-center acquisition, calibrated rule k = 5, τ_fg = 4, τ_bg = 4). It spent 100 proposals on calibration and 1,610 on expert review (4.6% of the 35,212-proposal evaluation pool), handled the remaining 33,602 automatically, and got 28,040 of those right: 79.6% of the evaluation pool, or 83.5% of the automatic decisions. Zero proposals were left deferred.

    S9.4 Why this must be published¶

    1. A taxon string is not reproducible without the model that produced it. Two versions of the same classifier yield different taxa from the same image.
    2. Published uncertainty is what makes labels re-derivable. Machine labels are a snapshot of a model, not ground truth. A release that keeps source media, detection geometry, model identity, and per-rank accuracy can be re-labeled when better models arrive and the label sets compared meaningfully. One shipping only final taxon strings cannot.
    3. Aggregate accuracy hides the rank-dependent failure mode above.
    4. Verification status must be per record, not per dataset — a README caveat cannot be filtered on.

    S11.2 Current release checks¶

    The generator now parses every date, time, and coordinate pair and rejects sentinel values (nan, None, NULL, -1, 1970-01-01) before export. The release audit checks, over every modality and merged table:

    • source-to-merged parity for Events and Occurrences;
    • a single-rooted Event hierarchy with no dangling parentEventID;
    • Occurrence-to-Event links and ancestry;
    • parsed dates and times, and WGS84-bounded coordinates;
    • every Occurrence date inside its parent Event's span and the study window;
    • no absolute cluster paths, and every associatedMedia resolving to a released file in the dataset's media manifest;
    • agreement between the generator and the released tables.

    S14.1 Release discipline¶

    Integration passes are dated and immutable. Every mutation retains a before-copy and emits a JSON audit record. Passes differ semantically, not just additively — different visual-label semantics, corrected timestamps — so comparing numbers across passes is invalid in a way that is not visible in the numbers. Any figure or table must name the release build it was computed from.

    The 2026-10-22 release build supersedes the 2026-07-24 pass; each of its repairs (S10, S3, S4, S16) has its own JSON audit record, shipped under metadata/provenance/. The 2026-09-20 curated-bird update is reconstructible from:

    • curated_bird_dwc_update_audit_20260920_015706.json
    • curated_bird_event_sync_audit_20260920_020046.json
    • curated_bird_project_sample_size_fix_20260920_020401.json
